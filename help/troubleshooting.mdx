# 排查问题

先看基础状态,不要反复重装,也不要把凭据贴到任何地方:

```bash
recodex status
recodex doctor
```

`doctor` 会逐项报告客户端安装、托管配置、登录、凭据、网关、订阅与 Codex 可用性 —— 大多数问题看它一眼就知道卡在哪一环。

## 装不上 / 找不到

### 找不到 `recodex`

一键安装脚本会把它加进 PATH,但**已经打开的终端读不到** —— 新开一个终端再试:

```bash
recodex version
```

### `install check` 或 `doctor` 说没装 Codex,但我明明装了

先确认官方 Codex 客户端确实在。如果你是从\*\*应用商店(MSIX)\*\*装的,它不在 `Programs` 目录下,而在 `C:\Program Files\WindowsApps\` —— ReCodex 会去注册表查这类安装,`recodex install check` 应当能认出来。

若仍报未安装,把 `recodex doctor --json` 的输出发给客服。

## 登录相关

### `recodex login` 一直等在那里

- **浏览器没打开**:用终端里显示的验证地址手动打开。
- **提示设备数已达上限**:每个账号最多 3 台。命令行会列出当前设备让你选一台撤销;桌面端会提示你去[设备管理](https://recodex.dev/dashboard/devices)撤销。撤销之后**不用重新登录**,轮询会自己走通。
- **已经批准了但还在等**:检查网络,然后重新发起一次。

### 桌面端登录成功了,左下角还是官方账号

侧边栏那个名字会**立刻**变过来。如果没变,点一次面板里的「刷新额度」。

但**官方 Codex 真正用上你的账号需要重启一次** —— 那个进程在你登录之前就启动了,读不到新写入的配置。面板上点「立即重启生效」即可。

### `status` 说已登录,但 `account` / `usage` 报错

说明这台设备在服务端被注销了(比如你在别处撤销了它,或做过接管)。重新 `recodex login` 即可。

<Note>
  新版本的 `status` 会直接显示「凭据已失效」,而不是照本地文件说「已登录」。
</Note>

## 切回官方 ChatGPT 之后

### 历史对话打不开,提示 `Model provider recodex not found`

**升级到最新版即可**。旧版本在切回官方模式时会把 ReCodex 的 provider 定义整块删掉,而 Codex 把每个会话当时用的 provider 记在会话文件里 —— 定义没了,旧对话就解析不到。

新版本只摘掉默认选择、保留定义:新对话走官方账号,历史对话照常打开。

## Codex 报错

### 401 / 凭据过期

通常重新 `recodex login` 即可。Windows 上还要注意:登录写入的 `RECODEX_KEY` 对**已打开的**终端不可见,新开一个终端再试。

### 403

可能来自订阅状态、绑定关系或上游账号,**不要一律理解成封号**。先跑 `recodex doctor`,它会区分是订阅问题还是配置问题。

### 429 或额度耗尽

表示触发了频率或用量窗口限制。看一眼额度:

```bash
recodex usage --refresh
```

等窗口恢复即可,不要连续重试。

### 感觉变慢

换个网关试试:

```bash
recodex gateways        # 看各线路延迟
recodex gateways auto   # 自动选最快的
```

## 额度显示

### 显示「数据可能不是最新的」

额度是服务端快照,不是实时值。超过 5 分钟没更新就会这么标注,同时客户端会在后台自动补一次刷新;你也可以手动点「刷新额度」立刻更新。

### 看不到 5 小时窗口

近 5 小时没有用量时,上游不会返回这个窗口,所以界面上不显示。这是正常的,不是丢数据。

## 配置冲突

```bash
recodex doctor --fix
```

`--fix` 只处理能安全自动修复的项。如果报告 `config.toml` 有重复键,先备份,再删掉你手工加的、与 ReCodex 托管块重复的字段。

<Note>
  ReCodex 只动 `# >>> recodex managed block` 标记之间的内容,你自己的配置不会被覆盖。
</Note>

## 支付成功但订阅不可用

确认订单不是处理中,刷新账单与订阅页并重新登录。仍未生效时提交订单号、支付时间和页面状态 —— **不要**提交支付密码或完整付款凭证。

## 收集脱敏诊断

```bash
recodex doctor --json
recodex logs --limit 50
```

两者都是脱敏的(日志只含命令名、结果、版本、系统)。发送前仍建议扫一眼有没有项目名或文件路径。

## 还是不行

提交支持请求时带上:发生时间(到分钟)、操作系统、`recodex version` 的输出、`doctor --json` 的结果,以及最短复现步骤。

<Warning>
  不要发送原始密钥、设备授权码、密码、数据库连接串或未脱敏日志。ReCodex 客服不会向你索取这些。
</Warning>
