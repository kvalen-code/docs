# 登入與授權

桌面端和命令列走的是**同一套裝置授權流程**:客戶端申請一個授權碼,你在瀏覽器裡批准這台裝置。

批准這一步只能由你本人完成 —— ReCodex 不會向你索取 ChatGPT 密碼。

## 桌面端登入

點右下角的 **Rx** 打開面板,在「帳號」頁點**登入 ReCodex**:

<Steps>
  <Step title="拿到授權碼">
    面板會顯示一個形如 `ABCD-1234` 的授權碼。
  </Step>
  <Step title="打開授權頁">
    點「打開授權頁」,瀏覽器會帶著授權碼打開確認頁面。若瀏覽器沒打開,面板會把地址顯示出來供你複製。
  </Step>
  <Step title="在瀏覽器裡批准">
    確認是你本人目前這台裝置,點批准。
  </Step>
  <Step title="重新啟動一次">
    面板會提示登入成功。**點「立即重新啟動生效」** —— 官方 Codex 行程在你登入之前就啟動了,讀不到新寫入的設定。
  </Step>
</Steps>

## 命令列登入

```bash
recodex login
```

終端顯示授權碼與驗證地址,並嘗試打開瀏覽器。批准後終端會提示成功。

### 瀏覽器沒有打開

複製終端本次列印的地址。**只用這一次輸出的地址**,不要用舊截圖裡的。

### 達到裝置上限

每個帳號最多同時授權 3 台裝置。

命令列會列出已登記的裝置,輸入要登出的編號即可 —— ReCodex 會撤銷那台並繼續本次登入;輸入 `q` 取消。

桌面端則會顯示「裝置數已達上限」並列出佔用的裝置,你到[裝置管理](https://recodex.dev/dashboard/devices)撤銷一台即可。**撤銷之後不用重新登入**,客戶端的輪詢會自己走通。

### 登入成功了但 Codex 仍報錯

Windows 上,登入寫入的 `RECODEX_KEY` 對**已經打開的**終端不可見。新開一個終端視窗,然後:

```bash
recodex status
recodex doctor
```

IDE 擴充和桌面客戶端同理 —— 需要重新啟動它們才能讀到新設定。

## 登入時改了什麼

- 在系統金鑰庫裡存下這台裝置的令牌(Windows 憑據管理員 / macOS 鑰匙圈)。
- 在 `~/.codex/config.toml` 寫入一段帶標記的**託管區塊**,只動這一塊。
- 把存取金鑰寫進使用者環境變數 `RECODEX_KEY`。

原有的 `config.toml` 和 `auth.json` 會先備份,`logout` 時按原樣還原。

## 重新整理託管設定

```bash
recodex refresh
```

伺服器節點或參數變化時用它重新拉設定,不需要重新登入,也不需要升級客戶端。

## 登出

```bash
recodex logout
```

會撤銷伺服器上的裝置工作階段、清除本機憑據,並還原登入前備份的 Codex 設定。網路暫時不通時,本機還原仍會繼續。

<Note>
  裝置身分(device id)是持久的:同一台機器重新登入不會額外佔用一個裝置名額。
</Note>
