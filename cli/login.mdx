# 登录与授权

桌面端和命令行走的是**同一套设备授权流程**:客户端申请一个授权码,你在浏览器里批准这台设备。

批准这一步只能由你本人完成 —— ReCodex 不会向你索取 ChatGPT 密码。

## 桌面端登录

点右下角的 **Rx** 打开面板,在「账号」页点**登录 ReCodex**:

<Steps>
  <Step title="拿到授权码">
    面板会显示一个形如 `ABCD-1234` 的授权码。
  </Step>
  <Step title="打开授权页">
    点「打开授权页」,浏览器会带着授权码打开确认页面。若浏览器没打开,面板会把地址显示出来供你复制。
  </Step>
  <Step title="在浏览器里批准">
    确认是你本人当前这台设备,点批准。
  </Step>
  <Step title="重启一次">
    面板会提示登录成功。**点「立即重启生效」** —— 官方 Codex 进程在你登录之前就启动了,读不到新写入的配置。
  </Step>
</Steps>

## 命令行登录

```bash
recodex login
```

终端显示授权码与验证地址,并尝试打开浏览器。批准后终端会提示成功。

### 浏览器没有打开

复制终端本次打印的地址。**只用这一次输出的地址**,不要用旧截图里的。

### 达到设备上限

每个账号最多同时授权 3 台设备。

命令行会列出已登记的设备,输入要退出的编号即可 —— ReCodex 会撤销那台并继续本次登录;输入 `q` 取消。

桌面端则会显示「设备数已达上限」并列出占用的设备,你到[设备管理](https://recodex.dev/dashboard/devices)撤销一台即可。**撤销之后不用重新登录**,客户端的轮询会自己走通。

### 登录成功了但 Codex 仍报错

Windows 上,登录写入的 `RECODEX_KEY` 对**已经打开的**终端不可见。新开一个终端窗口,然后:

```bash
recodex status
recodex doctor
```

IDE 扩展和桌面客户端同理 —— 需要重启它们才能读到新配置。

## 登录时改了什么

- 在系统密钥库里存下这台设备的令牌(Windows 凭据管理器 / macOS 钥匙串)。
- 在 `~/.codex/config.toml` 写入一段带标记的**托管块**,只动这一块。
- 把访问密钥写进用户环境变量 `RECODEX_KEY`。

原有的 `config.toml` 和 `auth.json` 会先备份,`logout` 时按原样还原。

## 刷新托管配置

```bash
recodex refresh
```

服务端节点或参数变化时用它重新拉配置,不需要重新登录,也不需要升级客户端。

## 退出登录

```bash
recodex logout
```

会撤销服务端的设备会话、清除本地凭据,并还原登录前备份的 Codex 配置。网络暂时不通时,本地还原仍会继续。

<Note>
  设备身份(device id)是持久的:同一台机器重新登录不会额外占用一个设备名额。
</Note>
