# Устранение неполадок

Сначала посмотрите базовое состояние. Не переустанавливайте по кругу и никуда не вставляйте свои учётные данные:

```bash
recodex status
recodex doctor
```

`doctor` по пунктам проверяет установку клиента, управляемую конфигурацию, вход, учётные данные, шлюз, подписку и доступность Codex — по его выводу обычно сразу видно, где затык.

## Не устанавливается / не находится

### Команда `recodex` не найдена

Скрипт установки добавляет её в PATH, но **уже открытые терминалы этого не видят**. Откройте новое окно:

```bash
recodex version
```

### `install check` или `doctor` говорит, что Codex не установлен, хотя он есть

Убедитесь, что официальный клиент Codex действительно установлен. Если он поставлен **из магазина приложений (MSIX)**, он лежит не в `Programs`, а в `C:\Program Files\WindowsApps\` — ReCodex ищет такие установки в реестре, и `recodex install check` должен их распознавать.

Если всё равно пишет «не установлен», отправьте в поддержку вывод `recodex doctor --json`.

### macOS пишет «разработчик не проверен» или «файл повреждён»

Пакет подписан ad-hoc (учётной записи разработчика Apple для нотаризации у нас пока нет), а браузер вешает на скачанный файл атрибут карантина.

Нажмите на ReCodex в Finder правой кнопкой и выберите **«Открыть»**, либо выполните:

```bash
xattr -dr com.apple.quarantine /Applications/ReCodex.app
```

## Вход

### `recodex login` бесконечно ждёт

- **Браузер не открылся** — откройте вручную адрес, показанный в терминале.
- **Достигнут лимит устройств** — на аккаунт их 3. CLI покажет список и предложит отозвать одно; десктоп отправит в [управление устройствами](https://recodex.dev/dashboard/devices). После отзыва **повторный вход не нужен**, опрос пройдёт сам.
- **Подтвердили, а он всё ждёт** — проверьте сеть и начните вход заново.

### Вход в десктопе прошёл, но слева внизу всё ещё официальный аккаунт

Имя в боковой панели меняется **сразу**. Если не изменилось — нажмите «Обновить квоту» в панели.

Но чтобы **официальный Codex действительно начал работать через ваш аккаунт, нужен один перезапуск**: его процесс стартовал раньше вашего входа и не видит новую конфигурацию. Нажмите «Перезапустить сейчас».

### `status` говорит «вход выполнен», а `account` / `usage` возвращают ошибку

Значит, устройство отозвано на сервере (например, вы отозвали его в другом месте). Выполните `recodex login` заново.

<Note>
  Новые версии `status` прямо пишут «учётные данные недействительны», а не докладывают о входе по локальному файлу.
</Note>

## После возврата на официальный ChatGPT

### Старые диалоги не открываются: `Model provider recodex not found`

**Обновитесь до последней версии.** Старые версии при переходе в официальный режим удаляли определение провайдера ReCodex целиком, а Codex записывает использованного провайдера в файл сессии — без определения старый диалог не разбирается.

Новые версии снимают только выбор по умолчанию, а определение оставляют: новые диалоги идут через официальный аккаунт, старые открываются как раньше.

## Ошибки Codex

### 401 / истёкшие учётные данные

Обычно помогает повторный `recodex login`. В Windows учтите: записанная при входе `RECODEX_KEY` **не видна уже открытым** терминалам — откройте новое окно.

### 403

Может быть связано со статусом подписки, привязкой или апстрим-аккаунтом — **это не обязательно бан**. Запустите `recodex doctor`: он различает проблемы подписки и конфигурации.

### 429 или исчерпана квота

Сработало ограничение частоты или окна расхода. Посмотрите квоту:

```bash
recodex usage --refresh
```

Дождитесь восстановления окна, не повторяйте запросы подряд.

### Стало медленнее

Смените шлюз:

```bash
recodex gateways        # задержки всех маршрутов
recodex gateways auto   # выбрать самый быстрый
```

## Отображение квоты

### Написано «данные могут быть неактуальны»

Квота — серверный снимок, а не значение в реальном времени. Пометка появляется, если данным больше 5 минут; клиент при этом делает фоновое обновление. Можно нажать «Обновить квоту» и получить свежие данные сразу.

### Не видно окна 5 часов

Если за последние 5 часов расхода не было, апстрим это окно не возвращает — в интерфейсе его нет. Это нормально, данные не теряются.

## Конфликты конфигурации

```bash
recodex doctor --fix
```

`--fix` чинит только то, что можно исправить безопасно. Если сообщается о дублирующихся ключах в `config.toml`, сделайте резервную копию и удалите добавленные вручную поля, дублирующие управляемый блок ReCodex.

<Note>
  ReCodex меняет только содержимое между маркерами `# >>> recodex managed block` — ваши собственные настройки не перезаписываются.
</Note>

## Оплата прошла, а подписка недоступна

Убедитесь, что заказ не в статусе «в обработке», обновите страницы счетов и подписки, войдите заново. Если не помогло — отправьте номер заказа, время оплаты и статус страницы. **Не отправляйте** платёжный пароль и полные платёжные реквизиты.

## Собрать обезличенную диагностику

```bash
recodex doctor --json
recodex logs --limit 50
```

Оба вывода обезличены (в журнале только имя команды, результат, версия и ОС). Перед отправкой всё же просмотрите их на предмет имён проектов и путей.

## Всё ещё не работает

В обращении укажите: время (с точностью до минуты), ОС, вывод `recodex version`, результат `doctor --json` и минимальные шаги воспроизведения.

<Warning>
  Не отправляйте исходные ключи, коды авторизации устройства, пароли, строки подключения к базам данных и необезличенные логи. Поддержка ReCodex их не запрашивает.
</Warning>
