# Вход и авторизация

Десктоп и CLI используют **один и тот же поток авторизации устройства**: клиент запрашивает код, вы подтверждаете это устройство в браузере.

Подтвердить может только владелец аккаунта — пароль от ChatGPT ReCodex не запрашивает.

## Вход в десктопном клиенте

Нажмите **Rx** в правом нижнем углу, вкладка «Аккаунт» → **Войти в ReCodex**:

<Steps>
  <Step title="Получите код">
    В панели появится код вида `ABCD-1234`.
  </Step>
  <Step title="Откройте страницу подтверждения">
    Нажмите «Открыть страницу авторизации» — браузер откроет подтверждение с этим кодом. Если браузер не открылся, панель покажет адрес для копирования.
  </Step>
  <Step title="Подтвердите в браузере">
    Убедитесь, что это ваше текущее устройство, и подтвердите.
  </Step>
  <Step title="Перезапустите один раз">
    Панель сообщит об успешном входе. Нажмите **«Перезапустить сейчас»** — процесс официального Codex стартовал до вашего входа и не видит новую конфигурацию.
  </Step>
</Steps>

## Вход из командной строки

```bash
recodex login
```

В терминале появятся код и адрес подтверждения, браузер откроется автоматически. После подтверждения терминал сообщит об успехе.

### Браузер не открылся

Скопируйте адрес, **напечатанный именно в этом запуске**. Не используйте адрес из старого скриншота.

### Достигнут лимит устройств

На аккаунт одновременно допускается 3 устройства.

CLI покажет список зарегистрированных устройств: введите номер того, которое нужно отключить — ReCodex отзовёт его и продолжит текущий вход. `q` — отмена.

Десктоп покажет «Достигнут лимит устройств» и список занятых слотов; отзовите одно в [управлении устройствами](https://recodex.dev/dashboard/devices). **Повторно входить не нужно** — опрос клиента пройдёт сам.

### Вход прошёл, но Codex всё равно ошибается

В Windows переменная `RECODEX_KEY`, записанная при входе, **не видна уже открытым** терминалам. Откройте новое окно и выполните:

```bash
recodex status
recodex doctor
```

С расширениями IDE и десктопными клиентами так же — их нужно перезапустить.

## Что меняется при входе

- Токен устройства сохраняется в системном хранилище (Диспетчер учётных данных Windows / связка ключей macOS).
- В `~/.codex/config.toml` пишется **управляемый блок** между маркерами — трогается только он.
- Ключ доступа записывается в пользовательскую переменную окружения `RECODEX_KEY`.

Существующие `config.toml` и `auth.json` предварительно сохраняются в резервную копию и восстанавливаются при `logout`.

## Обновить управляемую конфигурацию

```bash
recodex refresh
```

Забирает свежую конфигурацию при смене серверных узлов или параметров — без повторного входа и без обновления клиента.

## Выход

```bash
recodex logout
```

Отзывает сеанс устройства на сервере, удаляет локальные учётные данные и восстанавливает конфигурацию Codex, сохранённую до входа. Если сети временно нет, локальное восстановление всё равно выполняется.

<Note>
  Идентификатор устройства постоянный: повторный вход с той же машины не занимает дополнительный слот.
</Note>
